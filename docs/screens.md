## Personalization system
- **Passcode gate** (`PasscodeScreen.jsx`, `passcode.js`): every page load/refresh shows a full-screen passcode entry before anything else (`unlocked` state in `App.jsx`, deliberately not persisted). The code is `PASSCODE` in `src/passcode.js` (currently `DEMO`; 4 characters, capitalization ignored, checked automatically at 4 characters). Change it there and push. Under the box (below the "Incorrect code" slot), a 32 px note in `palette.primaryColor` (the Start button's sage) reads "This app is designed / to be used on your phone / in the usual vertical position." It's a casual in-app gate only — the code is readable in the built JS. While `RESET_ON_UNLOCK` is true, entering the code resets everyone to `TESTING_DEFAULTS` (Box Breathing, Shape D Morphing Sphere, Diagonal sliders, 6-6 target pace) via the normal localStorage-backed setters; set it to false to go back to remembering each person's last choices.
- **Select Mode screen** (`SelectModeScreen.jsx`) is the app's home/initial screen (`screen` state starts at `'selectMode'`) — a bold **HOME** title (`fontSize:32`, color `palette.headerColor` — active Teal Palette sage `#8db1a1`, shifted up via `transform: translateY(-96px)`), then an all-caps **MODES** subheading (color `palette.subheaderColor` — active Teal Palette light blue `#c2dafb`) styled to match the Art Options screen's title (`fontSize:24, fontWeight:300, letterSpacing:'0.1em'`) with its bottom margin fixed at 12px (1/8") above the first mode card — separate from the 16px gap between the cards themselves — sitting above the mode cards, the whole MODES+cards block shifted up via `transform: translateY(-96px)`. `OPTIONS` currently lists 3 selectable cards, in display order **Guided Breathing: Tutorial / Guided Breathing: Box Breathing / Guided Breathing: Slowing Down** (Own Pace `'basic'` is hidden too) — since Paced Breathing was hidden from the picker (its `{id:'timed',...}` entry removed from the array) while staying fully implemented and reachable via `mode === 'timed'` code paths elsewhere, same pattern as Shape Options A/C being hidden from the Art Options picker. Mode cards are **selectable, not immediate-start**: tapping a card calls `onSelectModeChange(id)`, which updates `selectedMode` — a localStorage-backed preference owned by `App.jsx` (key `selectedMode`, default `'tutorial'`, whitelist `['tutorial','timed','slowing','box']`, a saved `'basic'` moves to `'tutorial'`, mirrors the `sliderLayout`/`shapeOption`/`targetPace` pattern) — and shows a highlighted/checkmark selected state — same `optionBtn`-style pattern as the Shape Options cards, label color `palette.textColor` — without navigating away. Lifting this to `App.jsx` (rather than `SelectModeScreen`'s own local state, which reset every time the screen remounted on navigation) is what makes the selection survive returning to this screen from a mode or from any other screen. Bottom-center stacked group (`gap:20`): **Start** — a large (110px) circular button, translucent pink fill (`rgba(255,105,180,0.25)`, brightening to `0.75` alpha while pressed via `onPointerDown`/`onPointerUp`/`onPointerLeave`/`onPointerCancel`) with a `palette.headerColor` outline and label text (active Teal Palette sage `#8db1a1`); calls `onStart(selectedMode)`, actually launches the selected mode (this is where `handleSelectMode` now fires from) — above a row (`gap:12`) of two pill buttons: **Art Options** on the left (→ the Art Options screen; `onPersonalize` prop) and **Control Options** on the right (→ the Control Options screen; `onSliderLayouts` prop). There is no separate Home screen/hub — `HomeScreen.jsx` was removed and Select Mode absorbed its two entry points. Mode card labels are pulled from `MODE_LABELS` in `copy.js` (single source of truth shared with the top-center in-play label, see Modes section) — Basic's display label is **"Breathe at Your Own Pace"**, Slowing Down's is **"Guided Breathing: Slowing Down"**, Box Breathing's is **"Guided Breathing: Box Breathing"**; internal ids stay `'basic'`/`'slowing'`/`'box'`. `MODE_LABELS.timed` stays fully defined (used by the persistent top-center in-play label if Paced Breathing is ever launched, e.g. by restoring its card).

- **Breath Pace Options screen** (`BreathPaceOptionsScreen.jsx`, new) — 3 selectable cards sourced from `TARGET_PACES` in `src/breathPace.js` ("6 seconds in, 6 seconds out" default / "5 seconds in, 5 seconds out" / "4 seconds in, 6 seconds out"), same `optionBtn(selected, palette)` pattern (label color `palette.textColor`), no subtitle row. Title color `palette.headerColor`. Persisted via `targetPace` (localStorage, mirrors `sliderLayout`'s pattern). Reached only from the Slowing Down experience screen's unlabeled **Change Target Pace** button (top-left 28×28 square, `mode === 'slowing'` only) — its bottom-center nav button reads **"Back"** (the `onHome` prop name is unchanged internally, but the visible label was corrected from "Home" since it returns to `'experience'`, not `'selectMode'` — this screen is entered mid-session rather than from the app's true home, a deliberate one-off deviation from every other screen's Home behavior). See Modes → Slowing Down for the ramp mechanics this selection drives.
- **Option screens' bottom row** (`OptionsNav.jsx`, shared by Art Options and Control Options): **Home: Mode Options** pill on the left (→ Select Mode), a smaller Start in the middle (`StartButton.jsx`, the Home screen's Start at `size` 72 / 16 px font; calls `handleSelectMode(selectedMode)`, so it starts exactly like Home's Start), and a pill to the other option screen on the right (Control Options ↔ Art Options). A 13 px caption above the row names the mode Start will launch (`MODE_LABELS[selectedMode]`). The in-experience Home button still says Home.

Gap between stacked buttons: 20px. Positioned at `bottom: 16, left: '50%', transform: 'translateX(-50%)'`.
  - **Experience/breathing screen** (App.jsx overlay), **Vertical slider layout**: stacked center — **Home** / **Restart**. **Home** calls `handleBackFromExperience` (`setMode(null); setScreen('selectMode')`), returning to Select Mode.
  - **Experience/breathing screen, Diagonal slider layout**: not stacked — **Home** pinned bottom-left (`bottom:16, left:16`), **Restart** pinned bottom-right (`bottom:16, right:16`), matching the paintover reference.
  - **Art Options screen** (`PersonalizeScreen.jsx`, screen id stays `'personalize'`; on-screen title renamed from "Personalize" to **ART OPTIONS**): the shared option-screen bottom row (Home: Mode Options → `onSelectMode`, Start, Control Options).
- Art Options screen uses a scrollable cards container (`height: 380, overflowY: 'auto'`; layout is `justifyContent: 'flex-start'` with `paddingTop: 60, paddingBottom: 150` so cards don't slide under the bottom button group), and currently shows 7 cards in order: B "Morphing Cube with Targets", D "Morphing Sphere that Disappears", F Hot Air Balloon, G Paper Airplane, H Balloon, J Space Ship (grayed unless Blow on the Mic), I Input Test. **Shape Options:**
Options B and D are user-facing on the Art Options screen (`PersonalizeScreen.jsx`) — Options A, C and E remain fully implemented in code (Morph/Gates components, mode logic) but have no picker entry, so they're unreachable from the UI. Their internal ids (`'a'`/`'c'`/`'e'`) still exist everywhere else in the codebase unchanged. A saved `shapeOption` of `'e'` is migrated to `'d'` on load (`App.jsx`) so no one is stuck on the hidden Rotating Rings.
- **Option A**: sphere Morph + torus Gates (GatesA) — hidden from the Art Options picker
- **Option B** (listed first) — displayed as **"Morphing Cube with Targets"**: rounded-box Morph + cube-style Gates (GatesB)
- **Option C**: "Disappearing Morph" — sphere Morph that dissolves into a particle cloud (MorphC) + alternating Inhale torus / Exhale sphere gates (GatesC); exhale sphere pulses emissive as it crosses the Morph — hidden from the Art Options picker
- **Option D** (default) — displayed as **"Morphing Sphere that Disappears"**: reuses MorphC exactly, with no visible Gates or ties in Paced Breathing/Slowing Down (`GatesHeadless.jsx` renders nothing; breath pacing communicated entirely by `BackgroundA`, forced on for this option). **Box Breathing is the exception**: uses the same visible gates as Option C (`GatesBoxBreathingC.jsx`) plus `BackgroundA` layered on top.
- **Option E** — displayed as **"Rotating Rings"** (hidden from the Art Options picker): `MorphE.jsx`, 5 concentric torus rings that lie flat and coplanar on the horizontal plane at Exhale, and rotate into a fixed gyroscope/armillary-sphere pose at Inhale (outermost ring normal→X, second-outermost normal→Z, remaining inner rings random-but-fixed, chosen once at mount) — driven by the left slider only (`lv`), with a bounded per-ring "wobble" (`wobbleStrength = sin(π·lv)`, zero at both endpoints) layered on top of the base slerp so the transition tumbles organically while the two endpoint poses stay exact. Material is a plain `MeshStandardMaterial` (`color: palette.tertiaryColor`, `roughness` animated from `rv` same as other shapes) with **no emissive/Fresnel at all** in this first version. Fully headless like Option D in every mode, including Box Breathing (no `GatesBoxBreathingE` mesh file exists) — see Gate geometry section above. Pacing is carried entirely by `BackgroundB` (concentric rings) plus, in Box Breathing only, `StarFieldE` (see Background section).

**Color Palettes:**
- **Teal Palette** (active, locked in for all users — `palette = PALETTES.teal` in `App.jsx`): tertiaryColor=#276d8c, primaryColor=#8db1a1, secondaryColor=#0f3261, background=#1a1a3a, textColor=#c2dafb, headerColor=#8db1a1, subheaderColor=#c2dafb
- **Palette A**: tertiaryColor=#0a0a6e, primaryColor=#ff69b4, secondaryColor=#9955dd, background=#1a1028, textColor=#fbeedd, headerColor=#ff69b4, subheaderColor=#fbeedd — kept in `palettes.js`, was the active palette before the Teal Palette; currently unreachable in the UI (no picker), may return behind a future Color Options screen
- **Palette B**: tertiaryColor=#03455e, primaryColor=#12ffdb, secondaryColor=#5e4972, background=#002748, textColor=#fbeedd, headerColor=#ff69b4, subheaderColor=#fbeedd — also defined but currently unreachable in the UI (no picker)
- **Naming convention** (all palettes, current and future, follow this schema): `primaryColor`/`secondaryColor`/`tertiaryColor` are the 3D-scene accent/base colors (Morph emissive, Gates/rings, Morph body — see Morph material and Gate geometry sections), `background` is the scene + UI-overlay background, and `textColor`/`headerColor`/`subheaderColor` drive the screen overlays' body text/page titles/subheadings respectively (see Personalization system section for exactly which UI elements use each).
- **Experience-screen UI follows the live palette**: `PaletteLerpDriver` (App.jsx) writes CSS custom properties on the experience wrapper every frame — `--live-text-color` (all overlay text: tutorial text, mode caption, nav button labels, slider labels, BreathLengthControl), `--live-bg-color` (tutorial text outline), and `--live-primary-rgb` (an `r, g, b` triple). All experience-screen buttons (Home/Restart pills, Change Target Pace square) and sliders (Vertical, Diagonal, BreathLengthControl) share the colors in `src/uiColors.js`: a 1px `UI_EDGE` (primary 0.8) outline around a `UI_INTERIOR` (primary 0.25) background, plus `UI_FILL`/`UI_THUMB` for slider progress and thumbs. They shift with each breath-cycle palette. **Slider inhale/exhale labels** (both layouts) use `--inhale-label-color`/`--exhale-label-color`, also written by `PaletteLerpDriver`: live tertiary by default, and the label for the phase to breathe now eases (smoothstep, `LABEL_LERP_S` 1 s) to the live text color, back when the other phase begins. The same eased amount also takes opacity from `LABEL_DIM_OPACITY` 0.5 (tertiary) to 1 (lit), and fades in a primary-color "emissive" glow (`--*-label-glow`: stacked `text-shadow` layers with blurs of 1×/2×/4× `LABEL_GLOW_MULT` 10 px). Driven by App's `getLabelPhase`: Box Breathing from `startBoxArt` on, by the caption clock (Inhale + Hold-in → inhale, Exhale + Hold-out → exhale); Slowing Down from `startPacedArt` on, by `breathPhaseRef`; otherwise both stay tertiary. **Box Breathing "hold" labels** (Diagonal only): a "hold" above each "inhale" (`HOLD_LABEL_GAP` 4 px) and one centered between the tracks above the exhale thumbs (top at `HOLD_OUT_TOP_Y` 94 in the track box, where the tracks clear it by ~8 px each side), in the lit label look (live text color, full glow `--hold-label-glow`). App's `getHoldPhase` ('in' during Hold-in, 'out' during Hold-out, from the caption clock) drives `--hold-in-label-opacity`/`--hold-out-label-opacity` with the same `LABEL_LERP_S` ease, so each fades in as its Hold starts and out with its partner label as the next phase begins. The Diagonal track's edge is a stroke 1px wider on each side with the track masked out, so it's a thin outline that never stacks under the interior. Menu screens keep the fixed Teal Palette.
- All UI screens (Home, Art Options) use `palette.background` so the active palette's background color is consistent everywhere

**Background:**
- No user-facing picker — `backgroundOption` is a derived constant in `App.jsx`, not stored state: `shapeOption === 'e' ? 'b' : shapeOption === 'd' ? 'a' : 'none'`. Shape Options A/B/C always render no background; Shape Option D always renders `BackgroundA`, Shape Option E always renders `BackgroundB`, in every mode including Box Breathing (the derivation is shape-only, not mode-dependent). This exists because A/B/C already communicate breath pacing via visible Gates + ties, and layering the animated background on top of those was judged too visually noisy — Options D and E remove the Gates/ties in every mode and rely on the background as their pacing cue; in Box Breathing, Option D restores the visible gates (see Gate geometry section) and the background layers on top as a supplementary cue, while Option E stays fully headless even in Box Breathing and adds `StarFieldE` as its Box-Breathing-only supplementary cue instead.
- **`BackgroundA`**: 30 scattered RoundedBox cubes (same geometry as GatesB inhale cubes, args [0.5, 0.5, 0.5], radius 0.1) randomly distributed across X∈[−8, 8], Y∈[−10, −4], Z∈[−30, 5]. Material: `gateColor` / `morphEmissive`, transparent. Animate between **State A** (opacity=0, emissiveIntensity=0, Y offset −5 from spawn) and **State B** (opacity=0.1, emissiveIntensity=1, at spawn Y) driven by `breathPhaseRef` + `gatesEnabledRef`: State B during exhale phase (exhale gate crosses z=0), State A during inhale phase. Animation progresses toward State B (target=1) over `exhaleSecondsRef.current` seconds and toward State A (target=0) over `inhaleSecondsRef.current` seconds — direction-aware, so Slowing Down's asymmetric-pace ramp (see that section) is reflected here too; falls back to `spawnIntervalRef.current/2` for both directions (byte-identical to the old single-halfInterval behavior) whenever either ref is `null`, which is every mode except Slowing Down mid/post-ramp. Smoothstep-eased. Cubes remain hidden while `gatesEnabledRef.current` is false — invisible in Basic mode and before Text C in other modes.
- **`BackgroundB`** (Shape Option E only): 5 concentric torus rings (default/unrotated orientation, facing the camera like Gates torus meshes), sharing one material (`color: gateColor`, **no emissive**, `transparent`, `opacity: 0.6`), positioned in a group at `[0, 0.25, -2]` with radii stepped 0.6→2.4. Unlike `BackgroundA`'s per-mesh opacity/Y animation, the entire group's `scale` lerps 0→1 (0 at Inhale, full size at Exhale, matching the concept art), reusing `BackgroundA`'s exact `progressRef`/`target`/direction-aware-`halfInterval`/local-smoothstep timing logic (driven by the same `breathPhaseRef`/`gatesEnabledRef`/`spawnIntervalRef`/`inhaleSecondsRef`/`exhaleSecondsRef` props). The outer rings are expected to bleed past the screen edges on a portrait phone at full scale — intentional, matching the reference art — but the starting radius/position constants are a first pass meant to be tuned on-device.
- **`StarFieldE`** (Shape Option E, Box Breathing only): ~50 small always-visible spheres (radius 0.045) scattered across X∈[−8,8], Y∈[−3,6], Z∈[−30,5] (a different Y range than `BackgroundA`'s scatter, chosen because these stars have no reveal animation and need to already sit in view). Material matches the gate-material convention (`color: gateColor`, `emissive: emissiveColor`), sharing one instance across all stars whose `emissiveIntensity` is set every frame from `holdFlareRef.current` (0-2, written by `GatesBoxBreathingHeadlessE` — see Gate geometry section above). Intensity-only flare, no hue change — matches how the real gates actually behave despite reading as a "color change."
